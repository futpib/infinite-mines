# Infinite Mines acceptance contract

This file turns the product requirements from the originating Buzz thread into executable acceptance criteria. A change is not complete until its requirement is represented here and by a Playwright assertion under `tests/e2e/` (plus a unit test when the behavior has a pure engine boundary).

| ID | Requirement | Automated acceptance |
| --- | --- | --- |
| R01 | Recreate only the unbounded Infinite mode with deterministic lazy generation and no cell DOM. | `core.e2e.ts`: production LAN response, Infinite UI, WebGL board, no cell nodes, far-world lookup remains sparse. |
| R02 | Preserve the 25 px starting grid, 5×5 safe opening, five preset densities plus Custom, flags/questions, chording, auto-flagging, score/high score, health, Things, home, overview, touch, pan, and zoom loop. | `core.e2e.ts`, `controls.e2e.ts`, and engine tests exercise each mechanic in the production bundle. |
| R03 | The production preview must accept `claude-laptop.lan`. | `core.e2e.ts` sends the exact Host header and requires HTTP 200 plus the app document. |
| R04 | Rendering and dragging must be WebGL 2, event-driven, sparse, and structurally bounded. | `rendering.e2e.ts` requires one detailed-instance or pixel-texture draw, bounded cache, stable GPU uploads during camera-only movement, unchanged HUD, and no idle frames. |
| R05 | The HUD and board must have polished, responsive light and dark designs. | `visual.e2e.ts` locks desktop light/dark and mobile-settings screenshots and runs WCAG A/AA audits in every layout. |
| R06 | Detailed cells must have device-pixel-snapped one-CSS-pixel shared borders and clean HiDPI output. The Retina backing resolution and edge-snapping lattice remain stable throughout navigation. | `rendering.e2e.ts` checks the 2× cap under 3× emulation, fractional camera/zoom, the one-pixel border contract, and an unchanged backing store during mouse dragging. |
| R07 | System/browser color-scheme remains the default and live `prefers-color-scheme` changes drive native UI, browser chrome, CSS, and WebGL. A persisted Light or Dark setting overrides the browser immediately without replacing the game, and returning to System resumes live browser changes. | `visual.e2e.ts` checks the initial no-flash theme attributes, selector/default, hint/meta declarations, live System changes, manual Light/Dark override, reload persistence, immutable game seed, and restoration of live System behavior. |
| R08 | Guarded controls are the persisted default. Concealed desktop reveal actions accept Ctrl/Command-click or double-click; a single unmodified click stays blocked and shows its guidance only after the double-click window. A recognized double-click must never flash that guidance. Right-click/Shift-click mark, Classic restores ordinary reveal, and touch follows the guarded R47 mapping without needing a keyboard modifier. | `controls.e2e.ts` covers delayed single-click guidance, mutation-observed no-flash double-click behavior, one-action double-click behavior for covered and questioned cells, guarded, opened, flagged, Ctrl-right-click, Classic persistence, and the R47 touch paths. |
| R09 | The complete active game survives refresh: seed/field, topology, mode, exact density and generation rules, score, Things, health, bounds, opened/marked/exploded cells, and viewport. | `persistence.e2e.ts` compares exact before/after reload state and validates the versioned 9-byte sparse record. |
| R10 | Plain clicks on already revealed clues remain available for chord/auto-flag; the guard must not intercept non-opening clicks. | `controls.e2e.ts` asserts no guard warning for revealed/flagged cells and keeps covered/question cells protected. |
| R11 | The resting board cursor is the standard arrow, not a crosshair. | `controls.e2e.ts` checks computed cursor states. |
| R12 | Zoom-out reaches exactly 1 CSS pixel per tile without scanning the million covered cells in the viewport. | `rendering.e2e.ts` requires 1 px, pixel LOD, more than one million logical visible cells, a sparse state texture, and bounded frame cost. |
| R13 | At low zoom borders and glyphs disappear; each pixel color represents clue/flag/question/explosion/artifact state. | `rendering.e2e.ts` reads the WebGL framebuffer and matches state pixels to the active theme palette. |
| R14 | Mouse-down alone must not imply drag. Up to 7 px of Euclidean drift remains the original click; only crossing it pans and shows the grabbing cursor. | `controls.e2e.ts` drives real pointer input on both sides of the threshold. |
| R15 | Every future thread requirement must extend this contract before delivery. | Repository policy: update this matrix and add/adjust an E2E assertion in the same change. `npm test` runs unit, production build, and the full E2E contract. |
| R16 | A user must be able to identify a specific cell for debugging. Hover/touch exposes coordinates and visible state; copying includes the deterministic game context without revealing a concealed mine. | `cell-reference.e2e.ts` checks exact coordinate mapping, safe public state, deterministic seed/mode/density/generation/safe-origin/scale/theme context, clipboard output, mobile pointer input, and no locator DOM writes during active drag. |
| R17 | Health grants must match the original Infinite mode exactly: 3 starting health except 1 in Deathmatch, with score awards at 25,000 / 5,000 / 1,000 / 1,000 / 1,000,000,000 by ascending mode. | `core.e2e.ts` crosses the exact threshold in all five modes and checks both starting and awarded health against the live original bundle. |
| R18 | Hover must highlight the complete direct click footprint: the target cell plus every neighbor that a clue click would chord-open or auto-flag. It must not predict flood-fill or reveal concealed mines. | `cell-reference.e2e.ts` checks single-cell, chord, and auto-flag footprints, the fixed 19-marker visual pool, topology-specific bounds, and suppression during active drag. |
| R19 | Guarded-control guidance must use browser platform information: Command on Apple platforms and Ctrl elsewhere. Input remains compatible with both modifiers. | `controls.e2e.ts` emulates Apple and non-Apple platforms and checks the hint, settings/help descriptions, guard message, and successful platform modifier. |
| R20 | Hover must be subtle and must not redraw or mutate the WebGL board. Coordinate text must be rate-limited independently at extreme zoom. | `cell-reference.e2e.ts` drives 120 one-pixel hover steps and requires a fixed pool of translucent compositor-transformed markers, zero WebGL frames, zero instance uploads, and bounded locator text mutations. |
| R21 | Overall interaction performance must be measurable with a repeatable production-browser benchmark, not inferred from renderer submission time alone. | `performance.e2e.ts` measures detail/pixel hover, mouse drag, touch pinch/pan, wheel zoom, reveal, save, and idle behavior; records frame pacing, synchronous input cost, WebGL work, long tasks, and browser task/style/layout deltas; and enforces regression ceilings. `npm run benchmark` runs it directly. |
| R22 | Touchscreens at phone and desktop sizes must support the guarded R47 mark/reveal mapping, explicit Reveal/Flag selection, dead-zone one-finger panning, and focal two-finger pan/zoom without accidental cell actions. | `controls.e2e.ts` covers guarded and explicit-tool touch actions; `touchscreen.e2e.ts` drives trusted coarse-pointer input for the callout, large-screen tool visibility, one-finger pan, two-finger pan/zoom, action suppression, stable Retina rendering, and persisted viewport state. `performance.e2e.ts` benchmarks the pinch path. |
| R23 | Zooming between detailed glyphs and low-zoom state squares must crossfade continuously instead of switching in one frame. The sparse renderer may take over only after the detail contribution reaches zero. | `rendering.e2e.ts` samples the WebGL framebuffer and renderer diagnostics at five points across the 4–8 px transition, checks the smoothstep progression and endpoint/midpoint colors, and retains the single-draw contract. |
| R24 | Revealing a large field must not materially degrade camera movement, zoom, hover, or click interaction. Performance must be compared against a small-field baseline, not checked only against fixed ceilings. | `performance.e2e.ts` benchmarks the same four interaction paths with 1,024 versus 98,304 revealed cells, attaches both reports, enforces absolute and relative p95 ceilings, and requires stable state-texture uploads plus zero hover redraws. The pixel renderer iterates only intersecting state chunks and camera motion samples one overscanned state texture in a single full-screen draw. |
| R25 | A low-zoom pixel must approximate the blended visual average of its detailed tile, rather than using the raw glyph accent color. | `rendering.e2e.ts` averages the detailed framebuffer for a clue, flag, question, and explosion, then compares each channel with its one-pixel LOD representation. The runtime palette is derived from the actual themed sprite atlas and base fills. |
| R26 | The complete direct click footprint remains the default hover preview, but a persisted setting can reduce it to the directly hovered cell. The hovered cell must remain highlighted in both modes. | `cell-reference.e2e.ts` checks the default affected-cell footprint, settings state, immediate cell-only reduction, direct-cell visibility, reload persistence, and restoration of the complete footprint. |
| R27 | Outside Deathmatch, game over must offer an explicit cheat-death continuation that preserves the field and score, increments a run-local persisted cheat count, and grants successive Fibonacci health values (1, 1, 2, 3, 5, 8…). The decision previews the next grant. CHEATS stays absent until the first use, accumulates across repeated revivals and refreshes, and resets with the sequence on a new field. | `core.e2e.ts` drives three Impossible deaths and revivals through the visible game-over screen, checks the preview, 1/1/2 grants, conditional HUD state, exact field continuity, reload persistence, and reset. `model.test.ts` covers the longer sequence, overflow saturation, engine boundary, and backward-compatible snapshots. |
| R28 | The board must offer browser fullscreen and recoverable distraction-free play. The canvas is full-viewport from initial load with the topbar/HUD layered above it; hide/show leaves only the canvas, live gameplay hover highlight, one obvious restore action, and a subtle live health readout. It leaves the canvas box and WebGL frame count unchanged. Fullscreen state follows the Fullscreen API including external exit. | `controls.e2e.ts` enters/exits real browser fullscreen; checks initial overlay geometry, every non-gameplay surface, the compact health readout and its live update, persistent hover markers, unchanged canvas bounds and renderer frames, fixed-screen cell stability, hidden-mode pan/zoom and persistence, and restoration. |
| R29 | Controls auto-hide by default after 50 successful cell actions without a control interaction. Reveal, mark, question/clear, chord, and auto-flag actions count; hover, guarded no-ops, drag, pan, pinch, and wheel/scroll do not. Controls reset the count, hiding never occurs mid-action or over a decision surface, the current hover footprint remains visible, and a persisted setting can disable auto-hide. | `controls.e2e.ts` checks excluded navigation/scroll input, the exact 49/50 boundary, reset-on-control behavior, post-pointer-up hiding with persistent hover, restore action, and the persisted Never opt-out. |
| R30 | Automatic flagging must update the board silently; no singular or plural auto-flag toast is shown. | `core.e2e.ts` runs automatic flagging through the production action path, verifies the flags, and requires an empty status toast. |
| R31 | Beginning or ending a pan must not resnap the whole grid. Each one-CSS-pixel camera step translates every rendered grid edge by exactly one CSS pixel on the same device-pixel lattice, with no release-frame correction or redundant redraw. | `rendering.e2e.ts` reads actual WebGL border pixels before, during, and after a one-pixel pan under 3× device emulation, requires exact one-pixel edge displacement, stable backing resolution, and zero release frames, then retains the 35 ms p95 high-DPI frame-pacing ceiling. |
| R32 | The production document must ship a distinctive, scalable Infinite Mines favicon that remains legible at browser-tab size. | `core.e2e.ts` fetches the production SVG with the LAN Host header, validates its metadata, decodes it in Chromium, rasterizes it at 16 px, and requires opaque multi-color output. |
| R33 | A visible FPS counter must report active WebGL render cadence without creating an idle render loop. It shows `IDLE` after rendering stops and hides with the rest of the HUD in distraction-free mode. | `performance.e2e.ts` requires an initially visible idle counter, numeric output during a driven pan, stable frame count after returning to idle, and zero WebGL work for hover-only movement; `controls.e2e.ts` retains the exact hidden-mode surface contract. |
| R34 | WebGL redraw work must be proportional to visible damage when correctness and measured frame pacing permit it. Small cell actions redraw only a padded damage rectangle; integral one-device-pixel pans may scroll preserved pixels and redraw exposed strips, while fractional/high-DPI pans, zoom, resize, theme, and large damage fall back to a full frame. | `rendering.e2e.ts` compares partial output byte-for-byte with a forced full redraw, checks preserved untouched pixels, exact damage/blit areas, and fractional fallback; the high-DPI R31 test retains its full-frame pacing ceiling. `performance.e2e.ts` compares retained-strip pan against forced full rendering before the path is enabled. |
| R35 | Artifacts (Things) may exist only on safe cells whose visible clue is zero. Every new 24×24 zone has one simple Thing and an exact 25- or 36-cell mine-free footprint, using the original 5/6 versus 1/6 size probability; Square uses the original padded 5×5/6×6 placement, while alternate topologies retain the same cell count and protect every clue neighbor. Placement remains deterministic and sparse. Restoring a field saved before either generation change must retain its generation rules and reconcile a stale stored number at its Thing coordinate to opened zero before rendering. | `model.test.ts` checks exact footprint cardinality and size probability, one deterministic zero-clue Thing per zone, mine exclusion, negative seams, post-safe-start placement, and legacy-generation restore across the complete topology × difficulty matrix, plus stale-save reconciliation. `core.e2e.ts` discovers an unfiltered artifact through the production action path and verifies its zero clue and Things increment; `persistence.e2e.ts` loads an old numbered-Thing fixture and checks the migrated state and framebuffer. |
| R36 | Detailed grid lines must keep one top/left ownership lattice at every shared edge. Exposed borders beside covered cells and internal borders between rendered cells meet at corners without a one-pixel side switch across fractional pan, zoom, and HiDPI rendering. | `rendering.e2e.ts` reads the production WebGL framebuffer under 2× rendering, compares border-run widths and centroids on both sides of covered/open corner transitions at multiple fractional views, and requires a boundary-changing damage redraw to match a forced full frame byte-for-byte. |
| R37 | Every field has an immutable Square, Triangular, or Rhombille topology. Square is the clean-install and legacy-save default; clues count all edge-or-corner touching cells (8, 12, and 10 respectively). The selector is ordered by that neighbor count, and topology drives safe opening, mine/clue generation, flood/chord, hit-testing, polygon hover, detail/pixel LOD, overview, damage, references, and persistence. | `topology.test.ts` validates exact symmetric touching/edge graphs, geometry, negative-coordinate hit testing, and visible ranges. `model.test.ts` runs deterministic mine/clue/safe-zone/snapshot behavior across all topologies. `topology.e2e.ts` exercises the ordered production selector, polygon framebuffer/hit-test/hover, clue range, one-draw detail and pixel LOD, pan, reload, legacy migration, and Square default. |
| R38 | Every topology must render a contiguous plane without clear-color cracks. Hints, flags, questions, explosions, and artifacts stay upright in screen space instead of rotating with triangular or Rhombille cell axes. | `topology.e2e.ts` fills dense Square, Triangular, and Rhombille regions at a fractional view and requires zero clear-color pixels in the central framebuffer; it samples all three Rhombille orientations and requires the representative atlas glyph to remain vertically oriented. |
| R39 | On non-Square boards, hover must show every concealed cell counted by the hovered cell's hint as a second, visually distinct layer from the cells a click will directly affect. Revealed neighbors receive no hint marker. This remains compositor-only and survives hidden-controls mode. | `topology.e2e.ts` checks 10/12-cell topology neighborhoods with mixed revealed/concealed states, one-cell covered-click sets, distinct computed colors, unchanged WebGL frames, and hidden-mode persistence for Rhombille and Triangular fields. |
| R40 | Every topology × density choice owns an independent persisted field and viewport. Switching restores that exact slot or creates it once; changing a Custom percentage replaces only that topology's Custom slot, and restarting replaces only the active slot. The last active pair resumes after reload and legacy v1 saves migrate to Square without loss. | `persistence.e2e.ts` switches among Square/Rhombille Beginner/Master slots and compares their exact seeds, cells, densities, and views; checks the atomic active pointer and slot keys; restarts one slot without altering another; `core.e2e.ts` checks the Custom slot across reload; and `topology.e2e.ts` covers legacy migration. |
| R41 | The non-Square hint-neighborhood hover is enabled by default and can be disabled independently of the direct click-preview layer. The choice persists across reloads, applies immediately, and causes no WebGL redraw. | `topology.e2e.ts` checks default state, independent direct-marker continuity, immediate Show/Hide switching, local persistence, reload restoration, and zero renderer frames on Triangular fields. |
| R42 | Invalid flag layouts and explosions must always complete in bounded time on the infinite field. Over-flagged clues are no-ops; a wrong equal-count chord may detonate mines explicitly selected by that chord, but a blast cannot recursively traverse touching covered mines. These rules hold for every topology, negative coordinates, and chunk seams. | `model.test.ts` drives over-flagged and infinite-connected-mine adversaries across Square, Rhombille, and Triangular fields at positive/negative 64-cell seams; `core.e2e.ts` reproduces the reported Triangular/Impossible `(-7, -1)` clue-4 beside clue-2 with seed 84, requires a responsive trusted click, finite damage, no queued residue, and a covered secondary mine. |
| R43 | Every unit, build, browser, visual, accessibility, and performance acceptance test must run in GitHub Actions through the same reproducible container command available locally. The CI OS image, Node, npm, Playwright browsers, dependencies, action revisions, timezone, locale, worker count, and retry policy are pinned; failure diagnostics remain downloadable. | `ci.test.ts` locks the Docker digest and download checksums, exact package/lock versions, single `npm run test:docker` workflow entrypoint, pinned Actions, Ubuntu runner, no retries, and artifact retention. GitHub and local verification both execute the complete `npm test` command inside `Dockerfile.ci`. |
| R44 | A fatal board pointer sequence must stop at the game-over decision: the click synthesized from that same mouse or touch input cannot activate Cheat death or restart. The decision surface remains visible above distraction-free play, and only a fresh pointer press or keyboard activation may choose an action. | `controls.e2e.ts` aligns a mine beneath the future Cheat death action, detonates it with trusted mouse and touchscreen input, requires the untouched decision screen and zero cheats, repeats the touch path with controls hidden, then proves a fresh touch activates the choice. |
| R45 | New fields must reproduce 1000mines' mine distribution: independent deterministic per-cell sampling at the nominal 18%, 22%, 27%, 33%, and 33% presets, followed by the R35 Thing exclusion, for expected whole-field rates of 17.16%, 20.98%, 25.74%, 31.46%, and 31.46%. Settings also offers a persisted 12–50% Custom per-cell chance. The HUD and settings report the exact selected per-cell chance. Version-1/2/3 fields retain their stored density and pre-footprint generation until explicitly restarted so unopened cells never change under a saved run; version 4 records the active generation. | `model.test.ts` locks nominal and effective rates, exact Thing exclusion, custom sampling, range validation, minimum-density opening bounds, v4 generation persistence, and legacy inference. `core.e2e.ts` checks displayed presets, HUD/settings current state, custom selection, reload, and invalid input; `persistence.e2e.ts` injects a v3 pre-footprint field, verifies honest legacy reporting, and requires Restart to adopt the nominal preset plus original Thing footprints. |
| R46 | Deathmatch's single life is final: its game-over state must never offer Cheat death, must focus and emphasize Start a new field, and the model must reject revival without changing health or the cheat count. This remains true after restoring a lost Deathmatch field. | `core.e2e.ts` loses and reloads a Deathmatch field, requires the terminal copy and sole focused restart action, and calls the engine boundary directly. `model.test.ts` proves the rejected revival is mutation-free. |
| R47 | Default touch input follows the same risk ordering as guarded desktop input: a short tap cycles the reversible mark on a concealed tile, while holding arms reveal without mutation and a valid release commits it. Flags are a hard interlock; choosing the visibly active Reveal tool is an explicit tap-to-reveal override. Short taps and other non-hold actions show no preview. Crossing the valid reveal-hold threshold shows a bounded, public-state-only neighborhood outside the finger at exactly the field's current zoom. The image contains the complete symmetric immediate topology-neighbor ring instead of cutting it at a fixed rectangle; it has no coordinate label or surrounding padding, marks the exact commit target, and keeps the release cue in a separate non-occluding strip. Pan, pinch, pointer cancellation, and game-over transitions clear it without accidental actions. | `controls.e2e.ts` uses trusted touch input to prove quiet short taps, hold-without-mutation, threshold-only preview, release-to-reveal, flag lockout, question reveal, quiet explicit-tool actions, and fatal-input isolation. `touchscreen.e2e.ts` checks complete/tight topology-neighborhood bounds, the separate action strip, zero padding, board-scale/target geometry and framebuffer parity, delayed visibility, top-edge placement, pan/pinch/cancel clearing, detail/pixel zoom behavior, large-screen coarse input, and stable Retina navigation. |

Performance assertions emphasize stable architectural invariants (draw count, cache bounds, instance/state uploads, event-driven frames) and retain a deliberately generous 35 ms p95 ceiling for the bundled software-WebGL browser. Device-specific traces remain a separate validation layer.
