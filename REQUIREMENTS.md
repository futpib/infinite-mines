# Infinite Mines acceptance contract

This file turns the product requirements from the originating Buzz thread into executable acceptance criteria. A change is not complete until its requirement is represented here and by a Playwright assertion under `tests/e2e/` (plus a unit test when the behavior has a pure engine boundary).

| ID | Requirement | Automated acceptance |
| --- | --- | --- |
| R01 | Recreate only the unbounded Infinite mode with deterministic lazy generation and no cell DOM. | `core.e2e.ts`: production LAN response, Infinite UI, WebGL board, no cell nodes, far-world lookup remains sparse. |
| R02 | Preserve the 25 px starting grid, 5×5 safe opening, five densities, flags/questions, chording, auto-flagging, score/high score, health, Things, home, overview, touch, pan, and zoom loop. | `core.e2e.ts`, `controls.e2e.ts`, and engine tests exercise each mechanic in the production bundle. |
| R03 | The production preview must accept `claude-laptop.lan`. | `core.e2e.ts` sends the exact Host header and requires HTTP 200 plus the app document. |
| R04 | Rendering and dragging must be WebGL 2, event-driven, sparse, and structurally bounded. | `rendering.e2e.ts` requires one detailed-instance or pixel-texture draw, bounded cache, stable GPU uploads during camera-only movement, unchanged HUD, and no idle frames. |
| R05 | The HUD and board must have polished, responsive light and dark designs. | `visual.e2e.ts` locks desktop light/dark and mobile-settings screenshots and runs WCAG A/AA audits in every layout. |
| R06 | Detailed cells must have device-pixel-snapped one-CSS-pixel shared borders and clean HiDPI output. Active drag may use 1× and must restore Retina output. | `rendering.e2e.ts` checks the 2× cap under 3× emulation, fractional camera/zoom, the one-pixel border contract, and drag-time 1×/resting 2× switching. |
| R07 | System/browser color-scheme hints and live `prefers-color-scheme` changes must drive native UI, browser chrome, CSS, and WebGL. | `visual.e2e.ts` checks the hint/meta declarations and switches the live renderer without navigation or game replacement. |
| R08 | Guarded controls are the persisted default. Only concealed reveal actions need Ctrl/Command; right-click/Shift-click mark, Classic restores ordinary reveal, and touch needs no keyboard modifier. | `controls.e2e.ts` covers guarded, opened, flagged, questioned, Ctrl-right-click, Classic persistence, touch tool, and long-press paths. |
| R09 | The complete active game survives refresh: seed/field, mode, score, Things, health, bounds, opened/marked/exploded cells, and viewport. Starting a new game replaces it. | `persistence.e2e.ts` compares exact before/after reload state, validates the versioned 9-byte sparse record, and checks atomic replacement. |
| R10 | Plain clicks on already revealed clues remain available for chord/auto-flag; the guard must not intercept non-opening clicks. | `controls.e2e.ts` asserts no guard warning for revealed/flagged cells and keeps covered/question cells protected. |
| R11 | The resting board cursor is the standard arrow, not a crosshair. | `controls.e2e.ts` checks computed cursor states. |
| R12 | Zoom-out reaches exactly 1 CSS pixel per tile without scanning the million covered cells in the viewport. | `rendering.e2e.ts` requires 1 px, pixel LOD, more than one million logical visible cells, a sparse state texture, and bounded frame cost. |
| R13 | At low zoom borders and glyphs disappear; each pixel color represents clue/flag/question/explosion/artifact state. | `rendering.e2e.ts` reads the WebGL framebuffer and matches state pixels to the active theme palette. |
| R14 | Mouse-down alone must not imply drag. Up to 7 px of Euclidean drift remains the original click; only crossing it pans and shows the grabbing cursor. | `controls.e2e.ts` drives real pointer input on both sides of the threshold. |
| R15 | Every future thread requirement must extend this contract before delivery. | Repository policy: update this matrix and add/adjust an E2E assertion in the same change. `npm test` runs unit, production build, and the full E2E contract. |
| R16 | A user must be able to identify a specific cell for debugging. Hover/touch exposes coordinates and visible state; copying includes the deterministic game context without revealing a concealed mine. | `cell-reference.e2e.ts` checks exact coordinate mapping, safe public state, deterministic seed/mode/safe-origin/scale/theme context, clipboard output, mobile pointer input, and no locator DOM writes during active drag. |
| R17 | Health grants must match the original Infinite mode exactly: 3 starting health except 1 in Deathmatch, with score awards at 25,000 / 5,000 / 1,000 / 1,000 / 1,000,000,000 by ascending mode. | `core.e2e.ts` crosses the exact threshold in all five modes and checks both starting and awarded health against the live original bundle. |
| R18 | Hover must highlight the complete direct click footprint: the target cell plus every neighbor that a clue click would chord-open or auto-flag. It must not predict flood-fill or reveal concealed mines. | `cell-reference.e2e.ts` checks single-cell, chord, and auto-flag footprints, the fixed nine-marker visual pool, nine-cell bounds, and suppression during active drag. |
| R19 | Guarded-control guidance must use browser platform information: Command on Apple platforms and Ctrl elsewhere. Input remains compatible with both modifiers. | `controls.e2e.ts` emulates Apple and non-Apple platforms and checks the hint, settings/help descriptions, guard message, and successful platform modifier. |
| R20 | Hover must be subtle and must not redraw or mutate the WebGL board. Coordinate text must be rate-limited independently at extreme zoom. | `cell-reference.e2e.ts` drives 120 one-pixel hover steps and requires a fixed pool of translucent compositor-transformed markers, zero WebGL frames, zero instance uploads, and bounded locator text mutations. |
| R21 | Overall interaction performance must be measurable with a repeatable production-browser benchmark, not inferred from renderer submission time alone. | `performance.e2e.ts` measures detail/pixel hover, mouse drag, touch pinch/pan, wheel zoom, reveal, save, and idle behavior; records frame pacing, synchronous input cost, WebGL work, long tasks, and browser task/style/layout deltas; and enforces regression ceilings. `npm run benchmark` runs it directly. |
| R22 | Touchscreens at phone and desktop sizes must support tap-to-reveal, explicit Reveal/Flag selection, long-press marking, dead-zone one-finger panning, and focal two-finger pan/zoom without accidental cell actions. | `controls.e2e.ts` retains tap/tool/long-press coverage; `touchscreen.e2e.ts` drives trusted coarse-pointer input for large-screen tool visibility, one-finger pan, two-finger pan/zoom, action suppression, 1× active/Retina-restored rendering, and persisted viewport state. `performance.e2e.ts` benchmarks the pinch path. |
| R23 | Zooming between detailed glyphs and low-zoom state squares must crossfade continuously instead of switching in one frame. The sparse renderer may take over only after the detail contribution reaches zero. | `rendering.e2e.ts` samples the WebGL framebuffer and renderer diagnostics at five points across the 4–8 px transition, checks the smoothstep progression and endpoint/midpoint colors, and retains the single-draw contract. |
| R24 | Revealing a large field must not materially degrade camera movement, zoom, hover, or click interaction. Performance must be compared against a small-field baseline, not checked only against fixed ceilings. | `performance.e2e.ts` benchmarks the same four interaction paths with 1,024 versus 98,304 revealed cells, attaches both reports, enforces absolute and relative p95 ceilings, and requires stable state-texture uploads plus zero hover redraws. The pixel renderer iterates only intersecting state chunks and camera motion samples one overscanned state texture in a single full-screen draw. |
| R25 | A low-zoom pixel must approximate the blended visual average of its detailed tile, rather than using the raw glyph accent color. | `rendering.e2e.ts` averages the detailed framebuffer for a clue, flag, question, and explosion, then compares each channel with its one-pixel LOD representation. The runtime palette is derived from the actual themed sprite atlas and base fills. |
| R26 | The complete direct click footprint remains the default hover preview, but a persisted setting can reduce it to the directly hovered cell. The hovered cell must remain highlighted in both modes. | `cell-reference.e2e.ts` checks the default affected-cell footprint, settings state, immediate cell-only reduction, direct-cell visibility, reload persistence, and restoration of the complete footprint. |
| R27 | Game over must offer an explicit cheat-death continuation that preserves the field and score, restores one health, and increments a run-local persisted cheat count. CHEATS stays absent until the first use, accumulates across repeated revivals and refreshes, and resets on a new field. | `core.e2e.ts` drives repeated Deathmatch deaths and revivals through the visible game-over screen, checks conditional HUD state and exact field continuity, reloads the run, and verifies reset; `model.test.ts` covers the engine boundary and backward-compatible snapshot behavior. |
| R28 | The board must offer browser fullscreen and recoverable distraction-free play. Fullscreen state follows the Fullscreen API including external exit; hiding controls leaves only the expanded game canvas and one obvious restore action, without visually moving the world or corrupting the canonical persisted viewport. | `controls.e2e.ts` enters/exits real browser fullscreen; checks every non-canvas surface is hidden; verifies canvas expansion, fixed-screen cell stability, hidden-mode play, canonical view state, hidden-mode saving/reload, and restoration. |
| R29 | Controls auto-hide by default after 50 successful cell actions without a control interaction. Reveal, mark, question/clear, chord, and auto-flag actions count; hover, guarded no-ops, drag, pan, pinch, and wheel/scroll do not. Controls reset the count, hiding never occurs mid-action or over a decision surface, and a persisted setting can disable auto-hide. | `controls.e2e.ts` checks excluded navigation/scroll input, the exact 49/50 boundary, reset-on-control behavior, post-pointer-up hiding, persistent restore action, and the persisted Never opt-out. |
| R30 | Automatic flagging must update the board silently; no singular or plural auto-flag toast is shown. | `core.e2e.ts` runs automatic flagging through the production action path, verifies the flags, and requires an empty status toast. |

Performance assertions emphasize stable architectural invariants (draw count, cache bounds, instance/state uploads, event-driven frames) and retain a deliberately generous 35 ms p95 ceiling for the bundled software-WebGL browser. Device-specific traces remain a separate validation layer.
